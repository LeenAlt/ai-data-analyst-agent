# Technical Documentation

## 1. Technology stack

-   Python
-   Pandas / NumPy
-   LangChain
-   LangGraph
-   Groq via `langchain-groq`
-   Pydantic
-   Chroma
-   Sentence Transformers
-   LangSmith
-   Google Colab `userdata` for secrets

## 2. Data model

The notebook generates:

-   30 products across Electronics, Home, Apparel, Beauty, and Sports
-   300 customers across New, Regular, and VIP segments
-   4,160 orders covering 2026-01-01 through 2026-06-30
-   30 inventory records
-   30 marketing records

The data generation uses a fixed NumPy random seed and intentionally
creates business signals.

## 3. Analytical layer

Pydantic result models include:

-   `RevenueResult`
-   `SalesGrowthResult`
-   `ProductPerformance`
-   `CustomerMetricsResult`
-   `InventoryRiskProduct`
-   `InventoryRiskResult`
-   `CampaignPerformance`
-   `CorrelationResult`

The core functions operate on Pandas DataFrames. LangChain `@tool`
wrappers then expose those functions to LLM-driven agents.

## 4. Specialist agents

### Sales

Tools: - `revenue_tool` - `growth_tool` - `top_products_tool` -
`bottom_products_tool` - `sales_by_category_tool` -
`sales_by_region_tool`

### Customer

Tools: - `customer_metrics_tool` - `policy_lookup_tool`

### Inventory

Tool: - `inventory_risks_tool`

### Marketing

Tools: - `campaign_performance_tool` - `correlation_tool`

The generic `run_specialist_agent()` loop lets the LLM choose tools,
executes the selected calls, feeds their results back, and repeats until
a final answer is produced or the iteration limit is reached.

## 5. Routing

`RoutingDecision` contains four boolean specialist flags plus a
reasoning field. The manager uses structured LLM output to produce this
schema.

## 6. Parallel workflow

`@task` functions wrap the specialist calls.
`parallel_analysis_workflow` and `full_analysis_workflow` launch
selected tasks and then collect their futures. The aggregator runs after
specialist outputs are available.

## 7. Aggregation

`AggregatedAnalysis` separates:

-   facts
-   findings
-   possible causes
-   recommendations
-   confidence and limitations

The aggregator prompt explicitly prevents hypotheses from being placed
in the facts list.

## 8. RAG implementation

The policy pipeline is:

1.  Create five `.txt` policy files.
2.  Load them from `policies/`.
3.  Split them into chunks.
4.  Create Hugging Face embeddings.
5.  Store chunks in Chroma.
6.  Create a retriever with `k=3`.
7.  Wrap retrieval in `policy_lookup_tool`.
8.  Add the tool to the Customer Agent.

## 9. State and memory

Short-term state: `InMemorySaver` + `thread_id`.

Long-term memory: `InMemoryStore` + namespace
`("user_memories", "demo_user")`.

The two mechanisms are intentionally demonstrated separately.

## 10. Human approval

`analysis_with_approval_workflow` first performs analysis. If a
recommendation contains reorder/restock/replenish language, it pauses
using `interrupt()`. The workflow resumes with `Command(resume=...)`.

The actual procurement action is a simulation:

`Purchase order submitted: ...`

## 11. Error handling

The task retry policy uses: - max attempts: 4 for LLM-related tasks -
initial interval: 2 seconds - exponential backoff factor: 2 - max
interval: 30 seconds

A separate demo uses three attempts and deliberately raises
`ConnectionError` twice before succeeding.

`correlation_tool` checks campaign IDs before calling the correlation
calculation and returns a structured error for invalid IDs such as
`Campaign_Z`.

## 12. Observability

The notebook configures:

``` python
LANGSMITH_TRACING=true
LANGSMITH_ENDPOINT=https://api.smith.langchain.com
LANGSMITH_PROJECT=ai-data-analyst-agent-capstone
LANGCHAIN_TRACING_V2=true
LANGCHAIN_PROJECT=ai-data-analyst-agent-capstone
LANGCHAIN_CALLBACKS_BACKGROUND=false
```

The workflow is invoked after tracing is enabled,
`wait_for_all_tracers()` is called, and the project is queried through
the LangSmith client.

The captured project showed successful internal runs for the specialist
tasks, marketing tool, aggregator, ChatGroq, Pydantic parser, and
RunnableSequence.

## 13. Reproducibility and security

API keys are retrieved from Colab `userdata`. They are not hardcoded in
the project documentation.

The synthetic data can be regenerated by rerunning the data-generation
cells.

## 14. Known limitations

-   Synthetic rather than production data
-   Marketing metric is conversion efficiency, not true monetary ROI
-   Customer metrics lack month-level filtering
-   Inventory is a snapshot
-   Long-term memory is in-memory
-   An earlier 120B Groq call hit a daily token rate limit
-   The notebook contains experimental cells; final submission should be
    run cleanly from top to bottom
